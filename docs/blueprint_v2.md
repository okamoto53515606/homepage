広告モデルとアルゴリズムによる「作られた世論」に疲弊したWebメディアへのアンチテーゼとして開発する、個人運営のためのミニマムなメディアシステム。

## 2. v1からのパラダイムシフト（The "Why"）

前バージョンの公開時、「GUIの設定画面が多すぎて非エンジニアには結局詰む」「課金システムなのにアクセス集中で落ちるリスクがある」という実務的な批判を受けました。v2は、これらの課題に対する私なりの解答です。

| 変更項目 | v1の構成 | v2の構成 | 変更の理由（The Why） |
| :--- | :--- | :--- | :--- |
| **インフラ基盤** | Firebase | **AWS完結** | 各種設定画面を非エンジニアがポチポチ巡回するのは限界がある。AWSなら後述の「CDKによる完全自動化」が可能であり、プロ向けインフラを個人の手に落とし込めるため。 |
| **デプロイ手法** | 手動設定 + CLI | **AWS CDK + Copilot Agent** | 手順書を読ませるのではなく、**「ユーザーが発行したIAMキー（鍵）をAIエージェントに渡し、AIにCDKを実行させる」**のが最も簡単で確実だから。 |
| **フロントエンド** | Next.js (SSR/API) | **静的ファイル + CDN配信** | 課金システム（商売）である以上、「バズってアクセスが集中した時に落ちる」は絶対にあってはならない。無料記事はCDNエッジ配信の静的サイトに回帰することで、無限のスケーラビリティと爆速なロードを実現するため。 |
| **管理・認証** | 同一ドメイン内で権限管理 | **管理画面のドメイン・完全分離** | システムの堅牢性を極限まで高めるため。閲覧者はGoogle OAuth、管理者はCognitoと完全に切り離し、CMS特有の管理画面への攻撃リスクをネットワークレベルで遮断する。 |
| **AIカスタマイズ** | Firebase Studio (終了発表) | **VSCode + GitHub Copilot Agent** | AIに「ゼロイチの開発」をさせるのではなく、CDKで用意された強固な土台の上で、非エンジニアが「デザインやページ構成の変更（カスタマイズ）」を対話ベースで行うため。インフラがコード化（CDK）されているからこそ、エージェントは状況を完璧に把握できる。 |

## 3. 最大の難関と「手厚いフォロー」の約束 (Phase 0)

本システムは非エンジニア向けですが、「誰でも1クリックで」という嘘はつきません。
ユーザーにとっての**最大の難関は、コードを書くことではなく「前提となる各種アカウントの取得」**です。

**【ユーザーが自力で乗り越えるべき必須の前提条件】**
1. 独自ドメインの取得（DNS管理）
2. AWSアカウントの作成とアクセスキー（IAM）の発行
3. Stripeアカウントの作成とAPIキーの発行
4. GitHub Copilot（およびVSCode）のセットアップ
5. Google OAuth画面の設定

ここはAIエージェントが代行できない「人間の社会的な契約」の領域です。
そのため、本プロジェクトでは**この「Phase 0」を突破するための、スクリーンショットを多用した極めて手厚いマニュアルを完備**します。

この泥臭いアカウント作成と「鍵（APIキー）」の取得さえ人間が頑張れば、その鍵をVSCode上でCopilot Agentに渡した瞬間から、魔法のように全自動のインフラ構築とカスタマイズが始まります。

## 4. AI活用の哲学 (Philosophy) v2

**「AIは『開発ツール』から『専属のインフラ保守エンジニア』へ」**

インフラをAWS CDK（コード）で定義したのは、人間のためではありません。**AIエージェントがシステムのアーキテクチャ全体を俯瞰し、状況を正確に把握するための「設計図」としてCDKを採用**しました。

ユーザーはソースコードやAWSコンソールを理解する必要はありません。何かエラーが起きたり、デザインを変えたいときは、VSCode上でエージェントに「ここを変えて」「エラーを直して」と指示（Why）を出すだけです。AIエージェントがコードを修正し、デプロイ（How）まで完遂します。

## 5. 対立構造による差別化 (Manifesto)

### 🛡 コミュニティと透明性（対：世論操作）
*   **仕様:** 投稿者の「国コード」「推定地域」「日替わりハッシュID」の強制表示。
*   **目的:** 組織的な工作やbotによる世論誘導を可視化し、自律的な秩序を生み出す。

### 💰 マネタイズと持続性
*   **収益モデル:** サブスク・広告を排除し、都度課金（少額決済後にN日間見放題）を採用。
*   **インフラ投資:** 「商売の基盤」である以上、AWSの月額数百円の維持費は「絶対に落ちないための必要経費」として許容する。

### 🤖 開発プロセスと役割分担
| 評価軸 | 既存の常識 | 本プロジェクト (homepage v2) |
| :--- | :--- | :--- |
| **導入ハードル** | 丁寧なマニュアルを読み解いて設定 | **手厚い手順書は「鍵の取得」まで。あとはAIに「鍵（IAM）」を渡して全自動構築** |
| **障害対応** | 人間がログを見てググる | **AIがCDK定義とログを照合して自動修復** |
| **カスタマイズ** | 人間がコードを書きAIが補完する | **Director Mode（人間は指示を出すだけ。AIがコードを書き、承認してデプロイ）** |

### 🛠 エンジニアリング思想
| 評価軸 | 既存の常識 | 本プロジェクト (homepage v2) |
| :--- | :--- | :--- |
| **アーキテクチャ** | 多機能なフルスタック（Next.js等） | **静的ファイル＋CDNエッジ配信（極限の単純化と堅牢性）** |

| **ライセンス** | ソースコードの権利主張 | **Unlicense（権利放棄 / 理念の共有のみ）** |

## 6. 開発・運用要件

*   **プラットフォーム:** AWS (Amazon Web Services) 完結
*   **開発言語:** 検討中（AIエージェントが最もコンテキストを理解しやすく、保守性の高い言語スタックを検証の上で決定する）
*   **インフラ管理:** AWS CDK - AIエージェントが読み書きする共通言語。
*   **構成:**
    1.  **利用者サイト (Front):** CloudFront + S3 (静的ホスティングベース)。
        *   **キャッシュ戦略:** トップページや無料記事などの静的ファイルはCDNでエッジキャッシュし、極限の爆速ロードを実現する。一方、**動的要素（有料記事の閲覧、ログイン状態の判定、Stripe決済処理、コメントの投稿・表示）はCDNキャッシュの対象外**とし、セキュアかつリアルタイムな処理を保証する。
        *   **認証:** Google OAuth (ログインのみに利用)。
    2.  **管理サイト (Admin):** 完全に分離された別ドメイン基盤。
        *   **認証:** Amazon Cognito。
*   **決済:** Stripe（都度課金・領収書自動送信）。
*   **コメント機能:** v1の仕様を完全継承。

利用者はプログラミングを学びません。「AIをディレクションする方法」だけを学びます。人間は最初の「鍵」を用意し、あとの城造りは機械の代理人に任せる。これが、AI時代における真の「個人メディアの民主化」です。
