## 東京リージョンで動かせるか？→ **できます**

Cloud Runは `asia-northeast1` に対応していますので、東京リージョンへのデプロイは技術的に可能です。

### パフォーマンス改善について

**効果が大きい部分（サーバーサイド）:**
- Firebase Admin SDK経由のFirestoreアクセス（SSR/API Routes）のレイテンシが大幅に改善されます
- us-central1 → asia-northeast1 のネットワークRTTは **約100-150ms** あるため、Firestoreの読み書きが多いページでは体感できるレベルの改善が期待できます
- Firebase Storage (同プロジェクト) へのアクセスも改善される可能性があります

**効果が限定的な部分（クライアントサイド）:**
- クライアントからFirestoreへの直接アクセスがある場合、それはCloud Runのリージョンとは無関係です（クライアント→Firestore直通なので元々東京）

### 移行手順の概要

大まかに以下のステップになります：

1. **Dockerfileを用意**してNext.jsアプリをコンテナ化（現在AI Studioが自動ビルドしたイメージを使っているため、本番用に自前ビルドが必要）
2. **Artifact Registryリポジトリ**を `asia-northeast1` に作成
3. **Cloud Buildまたはローカル**でイメージをビルド＆プッシュ
4. **Cloud Run サービス**を `asia-northeast1` にデプロイ（環境変数・Secrets・サービスアカウントの設定込み）
5. **ドメインマッピング**を新リージョンのサービスに設定
6. DNS切り替え

### 注意点

- AI Studioが自動ビルドしたイメージ（`us-central1-docker.pkg.dev/...`）をそのまま `asia-northeast1` のCloud Runにデプロイすることも**一応可能**ですが、イメージプルのレイテンシが増えます。東京のArtifact Registryに自前でビルドする方がベターです
- AI Studio経由のPublish（CI/CD）は引き続き us-central1 に出るため、本番は**独自のビルド・デプロイパイプライン**を構築する必要があります
- 環境変数やSecrets（Stripe APIキー等）はAI Studio側のSecretsで管理されている可能性が高いので、Secret Managerの確認が必要です
