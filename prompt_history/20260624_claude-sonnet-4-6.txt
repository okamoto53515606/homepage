## ① 問題の原因：`maxOutputTokens` 未設定

### 現状の確認

generate-article-draft.ts の `definePrompt` に `config` フィールドが**一切ない**。

```ts
const articleDraftPrompt = ai.definePrompt({
  name: 'articleDraftPrompt',
  input: {schema: GenerateArticleDraftInputSchema},
  output: {schema: GenerateArticleDraftOutputSchema},
  // ← config: { maxOutputTokens: ... } がない
  prompt: `...`,
});
```

### トークン数の見積もり

| 項目 | 値 |
|---|---|
| Gemini 3.5 Flash 入力上限 | 1,048,576 トークン |
| Gemini 3.5 Flash 最大出力 | **65,536 トークン** |
| **デフォルト `maxOutputTokens`** | **約 8,192 トークン** ← 問題の根本 |

30KB の日本語手順書は約 **15,000〜20,000 入力トークン** なので入力制限は問題なし。

問題は**出力側**。デフォルト 8,192 トークン ≈ 日本語で約 6,000〜8,000 文字。30KB の手順書を元に `markdownContent` を生成すると優に超えてしまい、Gemini が出力を途中で打ち切る。

### 現象の対応

| 現象 | 理由 |
|---|---|
| 「登録完了しない」 | Genkitが構造化出力スキーマのJSONバリデーションに失敗（途切れたJSONをパースできず `output` が null） |
| 「途中でぶつぎりされた記事が作られた」 | genkitがJSONをギリギリパースできたが `markdownContent` フィールドが途中で切断された状態 |

### 最小限の修正方針（調査のみなので参考）

`definePrompt` に `config` を追加するだけで解決できる：

```ts
const articleDraftPrompt = ai.definePrompt({
  name: 'articleDraftPrompt',
  input: {schema: GenerateArticleDraftInputSchema},
  output: {schema: GenerateArticleDraftOutputSchema},
  config: { maxOutputTokens: 65536 },  // 最大値に設定
  prompt: `...`,
});
```

## ② `genkit` vs `@google/genai` 直接利用の比較

### まず誤解を解消

現在の `@genkit-ai/google-genai`（v1.20.0）は**内部で `@google/genai` を使っているラッパー**。Firebase ドキュメントでは「`@genkit-ai/googleai`（旧） の drop-in replacement」と明記されており、`@google/genai` の新機能はこのプラグイン経由でも使える。

| 観点 | genkit + @genkit-ai/google-genai | @google/genai 直接 |
|---|---|---|
| 新機能への追従 | プラグイン経由（数日〜数週のタイムラグ可能性） | Google DeepMind が直接提供、最速 |
| 構造化出力（JSON schema + Zod 検証） | 組み込み | 自前実装が必要 |
| フロー管理・デバッグ UI | 組み込み | なし |
| `markdownContent` の途切れ問題 | `maxOutputTokens` 設定で解決 | 自前で同様の設定が必要 |
| 移行コスト | なし | 両フロー全書き直し |
| **推奨** | **現状維持** | 特別な理由がない限り不要 |

### 結論

**乗り換えは不要**。今回の問題は `@google/genai` を使おうが使うまいが `maxOutputTokens` の設定問題なので、genkit のまま `config: { maxOutputTokens: 65536 }` を追加するのが最小コスト・最大効果の対応になる。

---

### ③ 現在の画像受け渡しが `@google/genai` で動くか（念のため）

generate-article-draft.ts の `{{media url=this contentType="image/jpeg"}}` は genkit の Dotprompt 機能で、**URL から画像をダウンロードして Base64 → `inlineData` としてマルチモーダル入力に変換**している。

`@google/genai` でも同等の実装は可能（URL fetch → Base64 → `{ inlineData: { mimeType, data } }`）だが、自前で実装することになる。現状の genkit のやり方で十分動作しており、移行するメリットはない。
