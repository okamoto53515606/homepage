## トップページが遅い原因

### 1. **2回のFirestoreクエリが直列実行されている**
data.tsで：
```javascript
// 1回目: 総件数を取得
const countSnapshot = await query.count().get();

// 2回目: 実際のデータを取得
const articlesSnapshot = await query
  .orderBy('updatedAt', 'desc')
  .limit(limit)
  .offset((page - 1) * limit)
  .get();
```
この2つのクエリが順番に実行されるため、ラウンドトリップが2回発生しています。

### 2. **`offset`の使用**
Firestoreの`offset`は、スキップされるドキュメントも内部的に読み込むため、記事数が増えると効率が悪くなります（特に2ページ目以降）。

### 3. **データ量の違い**
- **トップページ**: 30件の記事データを取得
- **記事ページ**: 1件のみ（`slug`インデックスで高速検索）

### 改善方法（参考）
1. `count()`とデータ取得を`Promise.all`で並行実行する
2. offsetの代わりにカーソルベースのページネーション（`startAfter`）を使う
3. 総件数のキャッシュを検討する

インデックスは適切に設定されているので、クエリ構造の問題が主な原因です。

## 推奨: Promise.all での並列化

現在のコード（直列実行）:
```javascript
const countSnapshot = await query.count().get();  // 1回目を待つ
const articlesSnapshot = await query...get();       // 2回目を待つ
```

改善後（並列実行）:
```javascript
const [countSnapshot, articlesSnapshot] = await Promise.all([
  query.count().get(),
  query.orderBy(...).limit(...).offset(...).get()
]);
```

### メリット
- **ロジック変更なし**: 取得するデータは完全に同じ
- **テスト容易**: 結果が変わらないので検証が簡単
- **効果**: ラウンドトリップが2回→1回（体感で30-50%改善の可能性）

### 注意点
- `query`オブジェクトを再利用する前に、orderBy/limit/offsetを適用する順序に注意が必要（クエリを分けて作成）
