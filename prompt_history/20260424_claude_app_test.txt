原因がわかりました。

**`ALL_VIEWER_EXCEPT_HOST_HEADER`** ポリシーにより、CloudFront はビューワーの `Host`（`d26dic5zq9f9xh.cloudfront.net`）を Lambda に転送**しません**。Lambda が受け取る `host` ヘッダーは Lambda Function URL のドメイン（`3aoz4...lambda-url...aws`）になります。そのため構築される `redirect_uri` は

```

```

となり、Cognito の許可リストに一致しないため `redirect_mismatch` が発生します。

AWS 公式の仕様が明確になりました。  
**CloudFront OAC + Lambda Function URL の body 付き動詞（POST/PUT/DELETE/PATCH）は、クライアントが `x-amz-content-sha256` に body の SHA256 を正しく入れる必要がある**（OAC は自動計算しない）。よって元の実装方針自体は正しく、先ほどの revert が正解です。

失敗要因は別にあります：

1. **DELETE**: `fetch()` で DELETE + body は仕様上送れますが、CloudFront を経由する際に body が落ちる／中間で変更される／Chrome の Fetch 挙動でハッシュが不一致、といったトラブルが発生しやすい経路です。AWS のサンプルもすべて POST/PUT で紹介されています。
