### CloudFront で 1 時間キャッシュは可能か？ → はい

CloudFront の **Cache Policy** で **Minimum TTL = 3600** に設定すれば、オリジンが `no-store` を返しても CloudFront 側でキャッシュされます。

#### 設定方法

**CloudFront Cache Policy** を作成：

| 項目 | 値 |
|------|-----|
| Minimum TTL | 3600（1 時間） |
| Maximum TTL | 3600 |
| Default TTL | 3600 |
| Cache Key に Query Strings を含める | Yes — `cursor`, `tag` など（ページネーション用） |

#### 注意点

1. **全ページに適用される** — `/admin/*` や認証系 API にはキャッシュを適用しないよう、CloudFront Behavior を分ける必要があります
2. **記事公開/更新時のキャッシュ無効化** — 管理画面で記事を更新しても最大 1 時間反映されない。CloudFront Invalidation（`/*`）の API 呼び出しを admin API に追加するか、許容するかの判断が必要
3. **ログイン状態の差異** — `session` cookie がある場合のレスポンスがキャッシュされると、未ログインユーザーにもログイン済み表示が出る可能性。ただしこのアプリはクライアント側で認証状態を管理しているため、**おそらく問題なし**（要確認）

#### 推奨構成

```
CloudFront Behaviors:
  /api/*           → キャッシュなし（CachingDisabled）
  /admin/*         → キャッシュなし（CachingDisabled）
  /media/*         → S3 オリジン、長期キャッシュ（既存）
  /*（デフォルト）  → Lambda オリジン、1 時間キャッシュ
```

この Behavior 分離は将来 Lambda デプロイ時の CDK InfraStack で設定するのが自然です。現時点では `next dev` でのローカル開発なので、この `no-store` は気にしなくて大丈夫です。
